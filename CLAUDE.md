# Lucky Finance — правила работы (читай первым)

Личный финансовый PWA: доход в RUB, траты в VND, крипта. Один файл `index.html`, ванильный JS, без сборки. Живёт на GitHub Pages: https://godoffear.github.io/lucky_finance/. Владелец говорит по-русски — отвечай по-русски, коротко и по делу.

## Как мы работаем (порядок обязателен)
1. **Любую правку сначала согласуй с пользователем**: коротко предложи, что и как сделаешь, и жди «да». Не начинай фичи без одобрения, даже из списка отложенного.
2. После «да»: реализуй, протестируй, закоммить и запушь в ветку сессии (ту, что назначена в задаче). PR не создавай, пока не попросят.
3. Покажи результат (скриншоты Playwright, если менялся вид) и спроси «Влить N в main?».
4. После «да» — `git push origin HEAD:main` (fast-forward). Деплой — workflow «pages build and deployment», обычно 1–2 минуты. Пользователю напомни: открыть приложение и нажать «Обновить» на плашке версии.
5. Если пользователь явно сказал «делай»/«да» на конкретное предложение — это и есть согласование, повторно не спрашивай.

## Каждый релиз
Одновременно меняй три места: `VERSION` в `index.html`, новую запись сверху массива `CHANGELOG` там же, `version.json`. Без этого баннер обновления не сработает. Иконка: при смене картинки меняй и имя файла (`icon-192-vN.png`, `icon-512-vN.png`, `sw.js`, `manifest.webmanifest`).

## Как тестировать
- Сервер: `python3 -m http.server 8765` в корне репозитория.
- Playwright (Chromium уже установлен, `playwright install` не запускать). Пример проверки без ошибок страницы: `NODE_PATH=/opt/node-tools/node_modules node tools/smoke.js` (если модуль `playwright` не находится, найди его через `npm root -g` или в `/opt/node-tools`).
- Приложение внутри IIFE: глобальных переменных в `page.evaluate` нет. Данные подсовывай через `localStorage['fin-mvp-v1']` в `addInitScript`; чистую логику проверяй, вырезая функции из текста `index.html`.
- Внешние запросы (курсы валют, GitHub API) из песочницы блокируются — мокай через `page.route`.
- Для ручного вида: `nav{position:static!important}` помогает со скриншотами полной страницы.

## Куда смотреть
- `DEVELOPMENT.md` — устройство приложения и принятые технические решения (FIFO, курсы, кеши, прогнозы, темы, копии).
- `docs/DECISIONS.md` — что пользователь решил, что отвергнул, что отложено. **Сверяйся перед тем как предлагать идеи.**

## Важные ограничения
- Репозиторий публичный: личные данные, токены, файлы резервных копий сюда не класть.
- Резервные копии пользователь выгружает в свой отдельный приватный репозиторий (кнопка в приложении). Доступа к ним у сессии нет, пока он не подключит репозиторий.
- GitHub — через инструменты `mcp__github__*` (если отключились, подгрузи их через ToolSearch `select:`), `gh` недоступен.
- Не менять формат хранения данных без миграции в `normalize()` и без согласования.
