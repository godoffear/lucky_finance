# Lucky Finance — правила работы, контекст и статус (читай первым)

Последнее обновление: 2026-11-11, версия приложения **4.4**.

## 1. Что это

Личное мультивалютное приложение для учёта финансов: доходы в RUB, траты в VND, крипта (USDT). Один файл `index.html`, ванильный JS, без сборки. Упаковано в **Android APK через Capacitor** (Samsung владельца), сайт на GitHub Pages служит источником обновлений: https://godoffear.github.io/lucky_finance/

- Репозиторий приложения (публичный): https://github.com/godoffear/lucky_finance
- Репозиторий резервных копий (приватный): https://github.com/godoffear/lucky_finance_backup, файлы `backups/LuckyFinance_backup_ГГГГ-ММ-ДД_ЧЧ-ММ.json`
- Локальная папка: `/Users/igotlucky/Downloads/ClaudeCODDE/lucky_finance` (Mac владельца)
- Остальные проекты владельца в соседних папках (Рацион, Тренер, игры), в этот репозиторий их не смешивать.

## 2. Как мы работаем (порядок обязателен)

1. **Любую правку сначала предложи** (коротко: что и как), жди «да». Без согласия не править, даже если идея из списка отложенного. Явное «делай» или «да» на конкретное предложение уже согласование.
2. После «да»: реализуй, протестируй, покажи результат (скриншот или цифры).
3. **Публикация только после отдельного «да»** («выкладывай»). Правило владельца: релизы и артефакты без согласия не публиковать.
4. После публикации: дождись, пока Pages отдаст новую версию, сверь SHA-256 всех файлов, сообщи, как обновиться на телефоне.
5. Отвечай **по-русски, коротко, по делу**, без лишней теории. Владелец не программист: объясняй простым языком, действия давай по шагам.
6. Не проси токены и пароли в чате. Токены владелец вводит в приложение сам. Ключ GitHub лежит в macOS keychain, `git push` и `gh` работают без ввода.
7. Не лицензированный советник: по расходам даёшь наблюдения по его данным, не инвестиционные советы.
8. Менять данные владельца (операции) можно только через разовую миграцию в `normalize()` после явного согласия, как `migPickle`, `migNov`. Копия данных в GitHub только для чтения.

## 3. Каждый релиз

Только веб-изменения (почти всегда):
1. Поменяй `VERSION` в `index.html`, добавь запись сверху `CHANGELOG` (храним 5 последних, лишнюю снизу удали).
2. `npm run sync` (пересоберёт `www/`, `version.json` со списком файлов и хешами).
3. `git add -A && git commit` (в конце сообщения: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`) и `git push origin main`.
4. Дождаться, пока `https://godoffear.github.io/lucky_finance/version.json` покажет новую версию (с параметром `?x=случайное`), затем сверить хеши всех файлов (node fetch, при таймауте IPv6 запускать с `--dns-result-order=ipv4first`).
5. Если сборка Pages застряла или упала: `gh run list -R godoffear/lucky_finance`, затем `gh run rerun <id>` или `gh api -X POST repos/godoffear/lucky_finance/pages/builds`. Параллельно две сборки одной версии не запускать (одна отменяет другую).
6. Владельцу сказать: «Ещё → Обновление приложения → Проверить обновление → Обновить сейчас».

Менялся нативный код (`android/`, плагины, разрешения)? Тогда нужен новый APK: поднять `versionCode`/`versionName` в `android/app/build.gradle` и `minApk` в `package.json`, `npm run sync`, `./gradlew assembleDebug` в `android/` (**JDK 21**, лежит в `jdk21/`; системная Java 25 не подходит), `npm run release:apk` (кладёт APK в `apk/LuckyFinance.apk`, пишет хеш в `version.json`), потом выкладывать. Подпись должна совпадать: собирать на этом Mac тем же debug-ключом. Текущий APK: build 5 (версия 3.3), все релизы 3.4–4.3 были чисто веб.

Страховка: если обновлённая веб-версия не запустилась 3 раза подряд, приложение откатывается на встроенную.

## 4. Как устроено обновление и копии

- **Веб-обновление:** `version.json` = версия, `minApk`, `notes`, список файлов `{p,h,s}`, запись про APK. Приложение скачивает файлы в `Directory.DATA/update/<ver>/`, проверяет SHA-256, переключает `WebView.setServerBasePath` + `persistServerBasePath`. Старые версии чистятся `updCleanup()`.
- **Обновление APK:** внутри приложения: скачивание с Pages, FileProvider, системная установка (разрешение REQUEST_INSTALL_PACKAGES). Google Play так не позволит.
- **Вечерняя копия на GitHub:** фоновая задача `GhBackupWorker` (WorkManager) берёт `files/lucky-mirror.json` и заливает в приватный репозиторий. Токен вводит сам владелец в приложении («Ещё → Копии»).
- **Копия файлом на телефоне:** Documents/LuckyFinance, хранит 14 файлов.
- **Виджеты:** три размера (2×2, 4×1, 4×2), валюта и «скрывать суммы» в настройках.

## 5. Модель данных и подводные камни

- Данные `S` в `localStorage['fin-mvp-v1']`. Счета: Наличные VND, Карта РФ (RUB), BIDV (VND), Крипта (USDT), VIETCOMBANK (VND).
- Типы операций: `income`, `expense`, `transfer`, `exchange`, `save`, `unsave`, `svadj`. Накопления — отдельный «карман»: `save` списывает со счёта, `unsave` возвращает, `svadj` меняет только накопления.
- Форма «Перевод» объединяет обмен и перевод: тип выбирается по валютам счетов (одна валюта = перевод, разные = обмен).
- **Миграции** в `normalize()` разовые, по флагам в `settings` (`migFood`, `migCafe`, `migPickle`, `migNov`). Они должны идти **до** `sanitize(s)`: иначе он выбросит неизвестные подкатегории.
- Не менять формат хранения без миграции и согласия. Репозиторий публичный: личные данные, токены и копии сюда не класть.
- Тест-копия из GitHub: `git clone https://github.com/godoffear/lucky_finance_backup` (работает через keychain), структура файла копии — это сам объект `S` на верхнем уровне.

## 6. Как тестировать

- Раздать `www/` локально: `python3 -m http.server <порт> --bind 127.0.0.1` в папке `www` (после `npm run build:www`). Порты 8765 и `localhost` могут занимать чужие сессии, использовать `127.0.0.1` и другой порт.
- Открывать во встроенном браузере (Claude Browser). Объект `S` и функции **не** глобальны для javascript-инструмента: данные подставляй через `localStorage['fin-mvp-v1']` и перезагрузку страницы (подойдёт и настоящая копия владельца), проверку делай через DOM (`document.body.innerText`, `querySelector`, `.click()`).
- Для нативной части: эмулятор Medium_Phone_API_37.0 нестабилен на 8 ГБ RAM, запускать с `-memory 2560 -cores 2 -gpu host -no-snapshot`; тест через `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`.
- После правок проверять консоль на ошибки (сообщения про `navigator.vibrate` в браузере нормальны).

## 9. Открытые вопросы и нерешённое

- **Накопления («фантомные деньги»):** владелец жаловался, что при возврате из накоплений сумма «плюсуется к общему». Ждём его конкретный пример (счета, суммы, итог до и после). Варианты: показывать пояснение перед возвратом, предупреждение у «Указать сумму накоплений», действие «Убрать из накоплений без зачисления на счёт». Без примера не делать.
- **Не проверено на реальном Samsung:** виджеты, вечерняя копия в GitHub (нужен токен владельца в приложении), установка APK 3.3 до конца, недельный отчёт и галочки на реальных данных на телефоне.
- **Расхождение 41 180 ₫:** поиск владелец отложил (выписка в банке платная). Октябрьское расхождение осталось неизвестным; сверка 1–4 ноября закрыта.
- **Идеи из обратной связи за октябрь (не согласованы):** переносить «ИИС т-банк» в накопления или инвестиции, возврат долга учитывать как перевод, разбить «Другое» на подкатегории.
- **Дальше по плану редизайна:** дальнейшая чистка «Отчёта» (показывать Капитал, теги, инвестиции только при наличии данных). Только после нового предложения и «да».
- Политика конфиденциальности: в тексте остался плейсхолдер `[ВАШ EMAIL]`, владелец email не давал. Публикация в Play Market не начата (аккаунт, ключ подписи, AAB).
