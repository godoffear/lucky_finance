# Lucky Finance — заметки для разработки

Этот файл — памятка для следующего чата/сессии (в том числе Claude Code), чтобы не объяснять всё заново. Основной файл приложения — `index.html`, один файл, без сборки, ванильный JS (ES5-совместимый стиль), без React/фреймворков.

## Что это
Личный финансовый трекер для человека с доходом в одной валюте (RUB) и тратами в другой (VND), плюс крипта. Устанавливается как PWA с GitHub Pages: https://godoffear.github.io/lucky_finance/

## Структура репозитория
- `index.html` — всё приложение (HTML+CSS+JS в одном файле)
- `manifest.webmanifest`, `sw.js` — PWA-обвязка (офлайн-кеш, установка на экран)
- `icon-192.png`, `icon-512.png` — иконка (четырёхлистный клевер в золотой подкове, с 2.23; исходник — SVG, всё важное в центральных 80% под маску Android)
- `version.json` — текущая версия; приложение сверяет её при открытии и показывает баннер «Доступно обновление», если на сервере версия новее
- `README.md` — короткое описание для гостя репозитория

**Важно при каждом обновлении:** менять `VERSION` в `index.html` (константа вверху `<script>`), добавлять запись в массив `CHANGELOG` (там же, список версий с describe) и обновлять `version.json` — иначе баннер обновления не сработает и легко потерять синхронизацию (уже случалось: `VERSION` и `CHANGELOG` разъезжались, когда патч-скрипт падал на середине).

## Ключевые решения, принятые в разработке
- **FIFO-учёт курса.** Деньги в иностранной валюте хранятся «партиями» (lots) с курсом на момент поступления; траты списываются по принципу «первым пришёл — первым ушёл», чтобы показывать реальную стоимость трат в основной валюте, а не по сегодняшнему курсу.
- **Курсы валют: приоритет** (с 2.18, переключателя «Свой/Официальный» больше нет). `rateInfo()`: 1) по FIFO — средний курс партий, которые сейчас лежат в этой валюте на счетах и в накоплениях (`fifoRate()`, только партии с известным курсом, без ориентировочных), 2) заданный вручную, 3) рыночный, 4) ЦБ РФ (запасной). Пункты 2–4 — это `rateExt()`; именно его вызывает `compute()` для денег без курса, чтобы не было зацикливания на ещё не посчитанных партиях.
- **Источник рыночных курсов** — один запрос на `https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies/usd.min.json` (основной) с запасным на `https://latest.currency-api.pages.dev/...` (тот же проект, второй сервер). Отдаёт сразу фиат и крипту. Курс ЦБ РФ — отдельно, `https://www.cbr-xml-daily.ru/daily_json.js`. Если какой-то источник падает, в `RATE_DIAG` остаётся текст ошибки браузера (`Failed to fetch` и т.п.), который показывается пользователю — это ценно для диагностики (CORS/блокировки на стороне провайдера, не баг приложения).
- **Ввод сумм.** В полях ввода (не в выводе) точка — разделитель тысяч, запятая — десятичная. См. функции `num()` (парсинг) и `inp()`/`fmtField()` (форматирование при вводе). Вывод (список операций, итоги) — обычный `Intl.NumberFormat('ru-RU')` с пробелами.
- **Обязательные категории vs постоянные платежи.** Траты в категориях из `S.settings.must` не идут в «повседневные траты в день» — они либо точно вычитаются в свою дату (если это оформлено как «Постоянный платёж», `S.rec`), либо усредняются за месяц (`U` в `runway()`), если платежа ещё нет. Если для категории+валюты уже есть хоть один постоянный платёж (`catCovered()`), все её нерегулярные траты полностью исключаются из усреднения — предполагается, что платёж уже всё покрывает.
- **Накопления** — виртуальный «карман» по валютам (`C.sav`), пополняется только вручную («Отложить» списывает со счёта) либо через «Указать сумму накоплений» (`svadj`-транзакция, без привязки к счёту — для случаев расхождения данных).
- **Текущая основная модель данных** — простой объект `S` (см. `fresh()`/`normalize()`), пересчитывается в `compute()` при каждом рендере. Все данные хранятся в `localStorage` под ключом `fin-mvp-v1`, бэкап — экспорт/импорт JSON-файла.
- **Кеш курсов и прогноза.** `rateToMain()` берёт курс из `RATE_CACHE`, `runway()` — из `RW_CACHE`; оба сбрасываются в `compute()` (и `RW_CACHE` ещё в `render()`). Значит, любое изменение, влияющее на курсы (операции, ручные курсы, `rateMode`, основная валюта, загрузка курсов), должно проходить через `commit()`/`compute()`, а не только `save()`+`render()`.
- **Чистка импортированных данных.** `normalize()` вызывает `sanitize()`: id, коды валют, даты и числа приводятся к безопасному виду, чтобы подменённая копия не вставила разметку в HTML. Новые поля, которые выводятся в HTML без `esc()`, добавлять туда же.
- **Сервис-воркер** (`sw.js`): страницы кешируются по пути без `?параметров`, `version.json` не кешируется, шрифты Google лежат в отдельном кеше `fin-fonts` (cache-first). При изменении списка файлов менять имя `CACHE`.
- **Прогнозы только после 30 дней данных** (`FC_DAYS`, `fcReady()`): до этого вместо «На сколько хватит» и «Прогноза на конец месяца» показывается заглушка с числом оставшихся дней. Решение пользователя — на 3–7 днях прогноз вводил в заблуждение.
- **«Насколько выгодно ты меняешь»** (экран «Обмен валюты», `fxQualityCard()`): твой курс в каждом из последних 20 обменов сравнивается с рыночным на дату обмена. Курсы на дату берутся из того же пакета `@fawazahmed0/currency-api@ГГГГ-ММ-ДД` (у него есть версия на каждый день) и кешируются в `localStorage` под ключом `fin-mvp-hist` — отдельно от данных, в резервную копию не попадают.
- **Счета в прогнозе** (`S.settings.fcExcl`, `fcIn()`): отдельно от «в общей сумме» (`a.excl`). Отключённый счёт не участвует в «На сколько хватит», «К концу месяца» и «Сколько менять» — ни остаток, ни траты, ни постоянные платежи с него. Выбор — кнопкой «Выбрать» в карточках прогноза.
- **Графики** — чистые SVG/HTML без библиотек. Цвета серий `--c1…--c5` и `--cother` заданы в `:root` для светлой и тёмной темы, проверены валидатором палитры на различимость (в т.ч. для дальтоников). Порядок цветов фиксированный: топ-5 + серое «Другое» (`topSegs()`), круг — `donut()`. Рядом с каждым кругом всегда подписанная легенда с суммами (у светлых цветов контраст с белым фоном ниже 3:1).
- **Категория «Продукты»** (бывшая «Еда»): старые данные переносятся один раз в `normalize()` по флагу `settings.migFood`.
- **Долги и займы** (`S.debts`): записная книжка, остатки счетов не меняет. `{id,dir:'lent'|'owe',who,amount,cur,date,due,note,paid:[{date,amount}]}`.
- **Теги**: `#слово` в заметке операции, итоги — карточка «Поездки и теги» в «Отчёте».
- **Финпомощник** (с 2.20, «Ещё → Финпомощник»): приложение не вызывает AI само. Кнопки выгружают сводку (`aiSummary()`: остатки, месяцы по категориям, платежи, лимиты, цель, теги, долги, курсы — без отдельных операций и заметок) файлом или текстом. Вопросы задаются на отдельной странице-артефакте в claude.ai (`HELPER_URL`), которая отвечает за счёт подписки Claude того, кто её открыл; страница проверяет `app:'lucky-finance', kind:'ai-summary'`. Меняя формат сводки, поднимай `v` и проверяй, что страница помощника её понимает.
- **Подкатегории** (с 2.22): словарь `SUBS` (пока только «Мопед»: Топливо / Обслуживание / Покупка), у операции поле `t.sub`. Подкатегория с `oneoff:true` — разовая трата: не входит в среднюю трату в день (`runway()`), в среднюю линию «Пульса» и в «Где найти деньги». Своих подкатегорий пользователь пока добавлять не может — отложено.
- **Отмена удаления**: все удаления идут через `undoable(fn,msg)` — снимок `S` и `nav` до изменения, 7 секунд на кнопку «Отменить» в тосте.
- **Обратная совместимость в `normalize()`.** Когда меняется значение по умолчанию для настройки (как в версии 2.17 с `must`), важно проверять дефолт против **исходных загруженных данных** (`o.settings.X`), а не против уже примененного `fresh()`-значения — иначе новый дефолт тихо «утекает» на старые сохранения без явного ключа. Грабли уже наступали один раз, см. git-историю.

## Как катить обновление вручную (если без Claude Code)
1. Поменять `VERSION`, добавить запись в `CHANGELOG`, обновить `version.json`.
2. Залить `index.html` + `version.json` в репозиторий (GitHub Contents API или просто через веб-интерфейс «Upload files», тот же путь, тот же SHA).
3. Через 10-20 секунд проверить через `GET /repos/.../contents/index.html` (Contents API, не `raw.githubusercontent.com` — у него бывает CDN-кеш) что `VERSION` реально обновился.
4. На телефоне — закрыть и открыть приложение; должен появиться баннер «Доступно обновление» (сверяет `version.json`), либо просто дождаться новой версии через кнопку в баннере.

## Чего в приложении осознанно нет
Голосовой ввод, ачивки, AI-советник, «финансовое зеркало» — были в исходном ТЗ, решили не делать (слишком тяжеловесно для пользы). Синхронизация между устройствами и пуш-уведомления — требуют сервера, решили не делать. Автобэкап в облако без действия пользователя — браузеры не позволяют файлу сохраняться без явного тапа пользователя (ограничение платформы, не наше).
