# AGENTS.md — Lucky Finance: правила, контекст и устройство (читай первым)

Один файл для всех исполнителей (Claude, Antigravity, Codex, Hermes и др.). Прежние `CLAUDE.md`, `DEVELOPMENT.md`, `HERMES_FINANCE.md` слиты сюда. `CLAUDE.md` теперь одна строка-отсылка.

Работаешь только с этим проектом. Не даёшь инвестиционных советов (не лицензированный советник): по расходам только наблюдения по данным владельца. Другие проекты владельца (Тренер, Рацион, игры, «Вьетнамский») не трогай.

## 0. Правила работы (обязательны)

**Начало каждой сессии:**
1. `git pull`, затем прочитать `AGENTS.md`, `docs/STATUS.md` и все файлы в `docs/inbox/` (кроме `done/`).
2. Убедиться, что папка синхронизирована с репозиторием `godoffear/lucky_finance` (`git status` чистый или понятный).

**Общение и вопросы:**
- Владелец говорит по-русски, не программист. Отвечай по-русски, коротко, простыми словами, без жаргона. Тексты в приложении на «вы», без канцелярита.
- **Лишних вопросов не задавай.** Делай по здравому смыслу, а спорные места опиши в `docs/STATUS.md`. Спрашивай, только если без ответа нельзя продолжить или есть риск потерять данные.
- **Подтверждение владельца нужно только перед выпуском версии** (когда обновление становится доступным на телефоне, см. раздел 3). Всё остальное (правки кода, документы, тесты, ветки) делай без согласования.

**После каждой правки:**
- обновить `docs/STATUS.md` (что сделано, кем, что дальше), сделать commit и push сразу;
- если выполнена задача из `docs/inbox/`, перенести её файл в `docs/inbox/done/` и дописать в `docs/STATUS.md`.

**Как не сломать выпуск.** Push в `main` с изменением кода или `version.json` равен выпуску: GitHub Pages сразу отдаёт новые файлы. Поэтому:
- документы, `docs/STATUS.md`, `docs/inbox/` пушатся в `main` сразу;
- **правки кода** коммить и пушь в ветку `dev` (`git push origin dev`) сразу после каждой правки; в `main` они попадают только при выпуске после «да» владельца;
- **не трогай `version.json` и `apk/LuckyFinance.apk` вручную**: они генерируются `npm run sync` и `npm run release:apk` и нужны для обновления приложения на телефоне.

**Hermes и задачи:** задачи от владельца присылает его ассистент Hermes. Он кладёт их в `docs/inbox/` (по одному файлу `ГГГГ-ММ-ДД-коротко.md`). Исполнитель берёт самую старую, выполняет, переносит в `docs/inbox/done/`.

**Секреты:** ключи, токены, пароли и копии данных в репозиторий и в чат не класть. `*.keystore`, `*.jks`, `node_modules/`, `build/`, `.gradle/`, `.DS_Store` в `.gitignore`.

## 3. Каждый релиз (выпуск версии — только после «да» владельца)

Только веб-изменения (почти всегда):
1. Поменяй `VERSION` в `index.html`, добавь запись сверху `CHANGELOG` (храним 5 последних, лишнюю снизу удали).
2. `npm run sync` (пересоберёт `www/`, `version.json` со списком файлов и хешами).
3. Выпуск делается из `main`: слей `dev` в `main` (`git checkout main && git merge dev`). `git add -A && git commit` (в конце сообщения: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`) и `git push origin main`.
4. Дождаться, пока `https://godoffear.github.io/lucky_finance/version.json` покажет новую версию (с параметром `?x=случайное`), затем сверить хеши всех файлов (node fetch, при таймауте IPv6 запускать с `--dns-result-order=ipv4first`).
5. Если сборка Pages застряла или упала: `gh run list -R godoffear/lucky_finance`, затем `gh run rerun <id>` или `gh api -X POST repos/godoffear/lucky_finance/pages/builds`. Параллельно две сборки одной версии не запускать (одна отменяет другую).
6. Владельцу сказать: «Ещё → Обновление приложения → Проверить обновление → Обновить сейчас».

Менялся нативный код (`android/`, плагины, разрешения)? Тогда нужен новый APK: поднять `versionCode`/`versionName` в `android/app/build.gradle` и `minApk` в `package.json`, `npm run sync`, `./gradlew assembleDebug` в `android/` (**JDK 21**, лежит в `jdk21/`; системная Java 25 не подходит), `npm run release:apk` (кладёт APK в `apk/LuckyFinance.apk`, пишет хеш в `version.json`), потом выкладывать. Подпись должна совпадать: собирать на этом Mac тем же debug-ключом. Текущий APK: build 5 (версия 3.3), все релизы 3.4–4.3 были чисто веб.

Страховка: если обновлённая веб-версия не запустилась 3 раза подряд, приложение откатывается на встроенную.

## 4. Как устроено обновление и копии

- **Веб-обновление:** `version.json` = версия, `minApk`, `notes`, список файлов `{p,h,s}`, запись про APK. Приложение скачивает файлы в `Directory.DATA/update/<ver>/`, проверяет SHA-256, переключает `WebView.setServerBasePath` + `persistServerBasePath`. Старые версии чистятся `updCleanup()`.
- **Обновление APK:** внутри приложения: скачивание с Pages, FileProvider, системная установка (разрешение REQUEST_INSTALL_PACKAGES). Google Play так не позволит.
- **Вечерняя копия на GitHub:** фоновая задача `GhBackupWorker` (WorkManager) берёт `files/lucky-mirror.json` и заливает в приватный репозиторий. Токен вводит сам владелец в приложении («Ещё → Копии»).
- **Копия файлом на телефоне:** Documents/LuckyFinance, хранит 14 файлов.
- **Виджеты:** три размера (2×2, 4×1, 4×2), валюта и «скрывать суммы» в настройках.

## 5. Модель данных и подводные камни

- Данные `S` в `localStorage['fin-mvp-v1']`. Счета: Наличные VND, Карта РФ (RUB), BIDV (VND), Крипта (USDT), VIETCOMBANK (VND).
- Типы операций: `income`, `expense`, `transfer`, `exchange`, `save`, `unsave`, `svadj`. Накопления — отдельный «карман»: `save` списывает со счёта, `unsave` возвращает, `svadj` меняет только накопления.
- Форма «Перевод» объединяет обмен и перевод: тип выбирается по валютам счетов (одна валюта = перевод, разные = обмен).
- **Миграции** в `normalize()` разовые, по флагам в `settings` (`migFood`, `migCafe`, `migPickle`, `migNov`). Они должны идти **до** `sanitize(s)`: иначе он выбросит неизвестные подкатегории.
- Не менять формат хранения без миграции и согласия. Репозиторий публичный: личные данные, токены и копии сюда не класть.
- Тест-копия из GitHub: `git clone https://github.com/godoffear/lucky_finance_backup` (работает через keychain), структура файла копии — это сам объект `S` на верхнем уровне.

## 6. Как тестировать

- Раздать `www/` локально: `python3 -m http.server <порт> --bind 127.0.0.1` в папке `www` (после `npm run build:www`). Порты 8765 и `localhost` могут занимать чужие сессии, использовать `127.0.0.1` и другой порт.
- Открывать во встроенном браузере (Claude Browser). Объект `S` и функции **не** глобальны для javascript-инструмента: данные подставляй через `localStorage['fin-mvp-v1']` и перезагрузку страницы (подойдёт и настоящая копия владельца), проверку делай через DOM (`document.body.innerText`, `querySelector`, `.click()`).
- Для нативной части: эмулятор Medium_Phone_API_37.0 нестабилен на 8 ГБ RAM, запускать с `-memory 2560 -cores 2 -gpu host -no-snapshot`; тест через `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`.
- После правок проверять консоль на ошибки (сообщения про `navigator.vibrate` в браузере нормальны).

## 9. Открытые вопросы и нерешённое

- **Накопления («фантомные деньги»):** владелец жаловался, что при возврате из накоплений сумма «плюсуется к общему». Ждём его конкретный пример (счета, суммы, итог до и после). Варианты: показывать пояснение перед возвратом, предупреждение у «Указать сумму накоплений», действие «Убрать из накоплений без зачисления на счёт». Без примера не делать.
- **Не проверено на реальном Samsung:** виджеты, вечерняя копия в GitHub (нужен токен владельца в приложении), установка APK 3.3 до конца, недельный отчёт и галочки на реальных данных на телефоне.
- **Расхождение 41 180 ₫:** поиск владелец отложил (выписка в банке платная). Октябрьское расхождение осталось неизвестным; сверка 1–4 ноября закрыта.
- **Идеи из обратной связи за октябрь (не согласованы):** переносить «ИИС т-банк» в накопления или инвестиции, возврат долга учитывать как перевод, разбить «Другое» на подкатегории.
- **Дальше по плану редизайна:** дальнейшая чистка «Отчёта» (показывать Капитал, теги, инвестиции только при наличии данных). Только после нового предложения и «да».
- Расхождение BIDV: по последним данным в приложении больше, чем в банке, на 41 180 ₫. Идея: сверять «Ending balance» из уведомления BIDV с остатком в приложении после каждой операции. Не реализовано.
- Т-Банк: формат SMS «Покупка/Оплата» вживую не видели. Чеки по фото в «Операциях» без группировки. Память получателей лежит в `localStorage` и теряется при восстановлении из копии.
- Политика конфиденциальности: в тексте остался плейсхолдер `[ВАШ EMAIL]`, владелец email не давал. Публикация в Play Market не начата (аккаунт, ключ подписи, AAB).

6. Если GitHub просит «Confirm access», пароль или 2FA, остановись и верни управление владельцу.
7. Не используй `rm -rf` с масками, перезаписывай через `cp -R`.

### Подробный порядок выпуска (после «да» владельца)
Обычно правки только веб, APK пересобирать не нужно.
1. Реализуй и **протестируй**:
   - `npm run build:www`, раздать `www/` локально: `python3 -m http.server <порт> --bind 127.0.0.1` в папке `www` (порты 8765 и `localhost` могут занимать чужие сессии, бери другой порт и `127.0.0.1`).
   - Открыть во встроенном браузере. Объект `S` и функции не глобальны для инструмента javascript: подставляй данные через `localStorage['fin-mvp-v1']` и перезагрузку (подойдёт настоящая копия владельца из `lucky_finance_backup`), проверяй через DOM (`document.body.innerText`, `querySelector`, `.click()`).
   - Консоль без ошибок (`navigator.vibrate` в браузере нормален).
2. Подними `VERSION` в `index.html`, добавь запись сверху в `CHANGELOG` (храним 5 последних, лишнюю снизу удали). Добавь запись в `docs/DECISIONS.md`.
3. `npm run sync` (пересоберёт `www/` и `version.json` с хешами).
4. `git add -A && git commit -m "Release X.Y: …"` и `git push origin main`.
5. Подожди, пока `https://godoffear.github.io/lucky_finance/version.json?x=<случайное>` покажет новую версию. Сверь SHA-256 всех файлов с `version.json` (node fetch; при таймауте IPv6: `node --dns-result-order=ipv4first`).
6. Если сборка Pages застряла или упала: `gh run list -R godoffear/lucky_finance`, затем `gh run rerun <id>` или `gh api -X POST repos/godoffear/lucky_finance/pages/builds`. Две сборки одной версии параллельно не запускай.
7. Сообщи владельцу (см. раздел 1, п. 7): «Ещё → Обновление приложения → Проверить обновление → Обновить сейчас».

**Если менялся нативный код** (`android/`, плагины, разрешения): подними `versionCode` и `versionName` в `android/app/build.gradle` и `minApk` в `package.json`, `npm run sync`, `./gradlew assembleDebug` в `android/` (JDK 21, подпись общим debug-ключом), `npm run release:apk` (кладёт APK в `apk/LuckyFinance.apk`, пишет хеш в `version.json`), затем выкладывай как выше. Пока на телефоне APK старее `minApk`, веб-обновления не применяются: владельцу нужно будет установить APK (в приложении: «Ещё → Обновление приложения», или прямая ссылка на Pages). Скажи ему об этом заранее.

Страховка в приложении: если обновлённая веб-версия не запустилась 3 раза подряд, оно откатывается на встроенную. Всё равно проверяй до публикации.

### Ещё подводные камни
- Миграции в `normalize()` разовые, по флагам в `settings`, и идут **до** `sanitize(s)`, иначе тот выбросит неизвестные подкатегории.
- На macOS `sed -i` требует суффикс (`sed -i ''`), для сложных правок надёжнее python.
- Не публикуй две сборки Pages одной версии параллельно.
- Samsung и службы: доступ к уведомлениям включается вручную, у установленного APK бывает «ограниченные настройки».
- Нативный эмулятор Medium_Phone_API_37.0 нестабилен на 8 ГБ RAM: запускать с `-memory 2560 -cores 2 -gpu host -no-snapshot`, тест через `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`.

## 14. Устройство приложения (бывший DEVELOPMENT.md)

Этот файл — памятка для следующего чата/сессии (в том числе Claude Code), чтобы не объяснять всё заново. Основной файл приложения — `index.html`, один файл, без сборки, ванильный JS (ES5-совместимый стиль), без React/фреймворков.

### Что это
Личный финансовый трекер для человека с доходом в одной валюте (RUB) и тратами в другой (VND), плюс крипта. Устанавливается как PWA с GitHub Pages: https://godoffear.github.io/lucky_finance/

### Структура репозитория
- `index.html` — всё приложение (HTML+CSS+JS в одном файле)
- `manifest.webmanifest`, `sw.js` — PWA-обвязка (офлайн-кеш, установка на экран)
- `icon-192-v2.png`, `icon-512-v2.png` — иконка (четырёхлистный клевер в золотой подкове, с 2.23; при смене картинки меняй и имя файла — иначе Chrome может не обновить ярлык; исходник — SVG, всё важное в центральных 80% под маску Android)
- `version.json` — текущая версия; приложение сверяет её при открытии и показывает баннер «Доступно обновление», если на сервере версия новее
- `README.md` — короткое описание для гостя репозитория

**Важно при каждом обновлении:** менять `VERSION` в `index.html` (константа вверху `<script>`), добавлять запись в массив `CHANGELOG` (там же, список версий с describe) и обновлять `version.json` — иначе баннер обновления не сработает и легко потерять синхронизацию (уже случалось: `VERSION` и `CHANGELOG` разъезжались, когда патч-скрипт падал на середине).

### Ключевые решения, принятые в разработке
- **FIFO-учёт курса.** Деньги в иностранной валюте хранятся «партиями» (lots) с курсом на момент поступления; траты списываются по принципу «первым пришёл — первым ушёл», чтобы показывать реальную стоимость трат в основной валюте, а не по сегодняшнему курсу.
- **Курсы валют: приоритет** (с 2.18, переключателя «Свой/Официальный» больше нет). `rateInfo()`: 1) по FIFO — средний курс партий, которые сейчас лежат в этой валюте на счетах и в накоплениях (`fifoRate()`, только партии с известным курсом, без ориентировочных), 2) заданный вручную, 3) рыночный, 4) ЦБ РФ (запасной). Пункты 2–4 — это `rateExt()`; именно его вызывает `compute()` для денег без курса, чтобы не было зацикливания на ещё не посчитанных партиях.
- **Источник рыночных курсов** — один запрос на `https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies/usd.min.json` (основной) с запасным на `https://latest.currency-api.pages.dev/...` (тот же проект, второй сервер). Отдаёт сразу фиат и крипту. Курс ЦБ РФ — отдельно, `https://www.cbr-xml-daily.ru/daily_json.js`. Если какой-то источник падает, в `RATE_DIAG` остаётся текст ошибки браузера (`Failed to fetch` и т.п.), который показывается пользователю — это ценно для диагностики (CORS/блокировки на стороне провайдера, не баг приложения).
- **Ввод сумм.** В полях ввода (не в выводе) точка — разделитель тысяч, запятая — десятичная. См. функции `num()` (парсинг) и `inp()`/`fmtField()` (форматирование при вводе). Вывод (список операций, итоги) — обычный `Intl.NumberFormat('ru-RU')` с пробелами.
- **Обязательные категории vs постоянные платежи.** Траты в категориях из `S.settings.must` не идут в «повседневные траты в день» — они либо точно вычитаются в свою дату (если это оформлено как «Постоянный платёж», `S.rec`), либо усредняются за месяц (`U` в `runway()`), если платежа ещё нет. Если для категории+валюты уже есть хоть один постоянный платёж (`catCovered()`), все её нерегулярные траты полностью исключаются из усреднения — предполагается, что платёж уже всё покрывает.
- **Накопления** — виртуальный «карман» по валютам (`C.sav`), пополняется только вручную («Отложить» списывает со счёта) либо через «Указать сумму накоплений» (`svadj`-транзакция, без привязки к счёту — для случаев расхождения данных).
- **Текущая основная модель данных** — простой объект `S` (см. `fresh()`/`normalize()`), пересчитывается в `compute()` при каждом рендере. Все данные хранятся в `localStorage` под ключом `fin-mvp-v1`, бэкап — экспорт/импорт JSON-файла.
- **Кеш курсов и прогноза.** `rateToMain()` берёт курс из `RATE_CACHE`, `runway()` — из `RW_CACHE`; оба сбрасываются в `compute()` (и `RW_CACHE` ещё в `render()`). Значит, любое изменение, влияющее на курсы (операции, ручные курсы, `rateMode`, основная валюта, загрузка курсов), должно проходить через `commit()`/`compute()`, а не только `save()`+`render()`.
- **Чистка импортированных данных.** `normalize()` вызывает `sanitize()`: id, коды валют, даты и числа приводятся к безопасному виду, чтобы подменённая копия не вставила разметку в HTML. Новые поля, которые выводятся в HTML без `esc()`, добавлять туда же.
- **Сервис-воркер** (`sw.js`): страницы кешируются по пути без `?параметров`, `version.json` не кешируется, шрифты Google лежат в отдельном кеше `fin-fonts` (cache-first). При изменении списка файлов менять имя `CACHE`.
- **Прогнозы только после 30 дней данных** (`FC_DAYS`, `fcReady()`): до этого вместо «На сколько хватит» и «Прогноза на конец месяца» показывается заглушка с числом оставшихся дней. Решение пользователя — на 3–7 днях прогноз вводил в заблуждение.
- **«Насколько выгодно ты меняешь»** (экран «Обмен валюты», `fxQualityCard()`): твой курс в каждом из последних 20 обменов сравнивается с рыночным на дату обмена. Курсы на дату берутся из того же пакета `@fawazahmed0/currency-api@ГГГГ-ММ-ДД` (у него есть версия на каждый день) и кешируются в `localStorage` под ключом `fin-mvp-hist` — отдельно от данных, в резервную копию не попадают.
- **Счета в прогнозе** (`S.settings.fcExcl`, `fcIn()`): отдельно от «в общей сумме» (`a.excl`). Отключённый счёт не участвует в «На сколько хватит», «К концу месяца» и «Сколько менять» — ни остаток, ни траты, ни постоянные платежи с него. Выбор — кнопкой «Выбрать» в карточках прогноза.
- **Графики** — чистые SVG/HTML без библиотек. Цвета серий `--c1…--c5` и `--cother` заданы в `:root` для светлой и тёмной темы, проверены валидатором палитры на различимость (в т.ч. для дальтоников). Порядок цветов фиксированный: топ-5 + серое «Другое» (`topSegs()`), круг — `donut()`. Рядом с каждым кругом всегда подписанная легенда с суммами (у светлых цветов контраст с белым фоном ниже 3:1).
- **Категория «Продукты»** (бывшая «Еда»): старые данные переносятся один раз в `normalize()` по флагу `settings.migFood`.
- **Долги и займы** (`S.debts`): записная книжка, остатки счетов не меняет. `{id,dir:'lent'|'owe',who,amount,cur,date,due,note,paid:[{date,amount}]}`.
- **Теги**: `#слово` в заметке операции, итоги — карточка «Поездки и теги» в «Отчёте».
- **Финпомощник** (с 2.20, «Ещё → Финпомощник»): приложение не вызывает AI само. Кнопки выгружают сводку (`aiSummary()`: остатки, месяцы по категориям, платежи, лимиты, цель, теги, долги, курсы — без отдельных операций и заметок) файлом или текстом. Вопросы задаются на отдельной странице-артефакте в claude.ai (`HELPER_URL`), которая отвечает за счёт подписки Claude того, кто её открыл; страница проверяет `app:'lucky-finance', kind:'ai-summary'`. Меняя формат сводки, поднимай `v` и проверяй, что страница помощника её понимает.
- **Подкатегории** (с 2.22): словарь `SUBS` (пока только «Мопед»: Топливо / Обслуживание / Покупка), у операции поле `t.sub`. Подкатегория с `oneoff:true` — разовая трата: не входит в среднюю трату в день (`runway()`), в среднюю линию «Пульса» и в «Где найти деньги». Своих подкатегорий пользователь пока добавлять не может — отложено.
- **Цветные темы** (с 2.26): `PALS` + CSS-блоки `:root[data-pal="…"]` (идут после блоков тёмной темы и перекрывают их). Каждая тема — полный набор токенов (включая цвета графиков `--c1…`) и перелив карточки `--hero-bg`. Выбор хранится в `localStorage` (`fin-mvp-palette`), как и светлая/тёмная, в резервную копию не попадает. Светлая/тёмная работает только для «Классики».
- **Категория «Мама»** (с 2.27): обычный расход в `EXP`, но `ONEOFF_CATS` исключает её (как разовые подкатегории) из средней траты в день и прогнозов через `isOneOff()`.
- **Копия на GitHub** (с 2.28, `ghUpload()`, `ghAuto()`, `ghCard()`): PUT в Contents API `backups/<bkName()>` приватного репозитория пользователя. Репозиторий и токен — `localStorage['fin-mvp-gh']`, не в `S` (не попадает в копии и сводку). Автовыгрузка — раз в день при открытии, если хеш данных (без `lastBackup`) изменился. Приложение не проверяет, приватный ли репозиторий.
- **Отмена удаления**: все удаления идут через `undoable(fn,msg)` — снимок `S` и `nav` до изменения, 7 секунд на кнопку «Отменить» в тосте.
- **Обратная совместимость в `normalize()`.** Когда меняется значение по умолчанию для настройки (как в версии 2.17 с `must`), важно проверять дефолт против **исходных загруженных данных** (`o.settings.X`), а не против уже примененного `fresh()`-значения — иначе новый дефолт тихо «утекает» на старые сохранения без явного ключа. Грабли уже наступали один раз, см. git-историю.

### Как катить обновление вручную (если без Claude Code)
1. Поменять `VERSION`, добавить запись в `CHANGELOG`, обновить `version.json`.
2. Залить `index.html` + `version.json` в репозиторий (GitHub Contents API или просто через веб-интерфейс «Upload files», тот же путь, тот же SHA).
3. Через 10-20 секунд проверить через `GET /repos/.../contents/index.html` (Contents API, не `raw.githubusercontent.com` — у него бывает CDN-кеш) что `VERSION` реально обновился.
4. На телефоне — закрыть и открыть приложение; должен появиться баннер «Доступно обновление» (сверяет `version.json`), либо просто дождаться новой версии через кнопку в баннере.

### Чего в приложении осознанно нет
Голосовой ввод, ачивки, AI-советник, «финансовое зеркало» — были в исходном ТЗ, решили не делать (слишком тяжеловесно для пользы). Синхронизация между устройствами и пуш-уведомления — требуют сервера, решили не делать. Автобэкап в файл без тапа браузеры не позволяют; обходной путь — выгрузка в GitHub по токену (с 2.28).
