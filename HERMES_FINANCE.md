## 4. Что за приложение

Один файл `index.html`, ванильный JS (стиль ES5), без сборки. Упаковано в Android APK через Capacitor. Доходы в RUB, траты в VND, крипта (USDT). Данные `S` лежат в `localStorage['fin-mvp-v1']`. Счета: Наличные VND, Карта РФ (RUB), BIDV (VND), Крипта (USDT), VIETCOMBANK (VND). Типы операций: `income`, `expense`, `transfer`, `exchange`, `save`, `unsave`, `svadj`.

**Версия на момент передачи: 4.12.** Что добавлено в последних версиях (подробности и причины в `docs/DECISIONS.md`):
- **4.6** «Чек по фото»: фото или галерея → Gemini (ключ владельца, `fin-mvp-gem`) → позиции переведены и разложены по категориям → проверка → счёт → по одному расходу на категорию (общий `rid`). Голосовой ввод владелец отверг.
- **4.7** Уведомления BIDV: нативный `NotificationListenerService` кладёт текст в очередь, веб разбирает (`bankParse`), на главной карточка «ждёт категории». Разделение по категориям, чек к операции, поступление как обмен/доход/перевод, память «получатель → категория».
- **4.8** SMS Т-Банка (`tbParse`), упрощённый экран «Ещё» (курсы в «Мои валюты», спойлеры).
- **4.9** Зелёные галочки / красные «!» у ключа Gemini, копии на GitHub, доступа к уведомлениям и SMS.
- **4.10** Подкатегории в банковских операциях (запоминаются для получателя), общий список с галочками «Записать отмеченные (N)», на главной строка «Нужно указать категорию · N», все тексты на «вы».
- **4.11** Заметка-карандаш ✎ к банковской операции (карточка, список, окно категории), выделенные поля окна категории.
- **4.12** Разовая миграция `migSub15`: подписка 15.11 на BIDV, 242 134 ₫ («Подписки», заметка «Подписка, сервер»).

Побочные ключи `localStorage` (не в копиях): `fin-mvp-gem`, `fin-mvp-gemok`, `fin-mvp-rcmap`, `fin-mvp-pend`, `fin-mvp-pdone`, `fin-mvp-rcpt`, `fin-mvp-rsub`, `fin-mvp-bacc`, `fin-mvp-pinc`, `fin-mvp-lastbank`. Ключ Gemini и токен GitHub в копии не попадают.

## 5. Открытые вопросы и известные пробелы (с чего можно начать)
- **Расхождение 41 180 ₫** между приложением и банком на BIDV (по последним данным в приложении больше, чем в банке). Причина неизвестна. Идея: сверять остаток из уведомления BIDV («Ending balance») с остатком в приложении после каждой операции и показывать расхождение. Не реализовано.
- «Накопления» («фантомные деньги»): ждём конкретный пример владельца, без него не менять.
- Не проверено на реальном Samsung: виджеты, вечерняя копия в GitHub, установка APK до конца, камера и Gemini на реальных вьетнамских чеках, захват уведомлений BIDV и SMS Т-Банка в фоне (Samsung усыпляет службы, нужны «Без ограничений» и разрешённые ограниченные настройки).
- Т-Банк: формат SMS «Покупка/Оплата» не видели вживую, разбор написан по образцу.
- Чеки по фото в «Операциях» показываются как отдельные строки «Чек · магазин», без группы.
- Память получателей лежит в `localStorage` и теряется при восстановлении из копии.
- Политика конфиденциальности: остался плейсхолдер `[ВАШ EMAIL]`, публикация в Play Market не начата.
- Идеи из обратной связи (не согласованы, но теперь на твоё усмотрение): переносить «ИИС т-банк» в накопления, возврат долга как перевод, разбить «Другое» на подкатегории.
- Отвергнуто, не предлагать заново: кольца лимитов на главном, тост «отложи после зарплаты», размытие суммы, голосовой ввод, ачивки, «финансовое зеркало», синхронизация между устройствами, пуши, переходы в браузер для обновления. Сверяйся с `docs/DECISIONS.md`.

## 6. Как выкладывать обновление (сам, без согласования)
Обычно правки только веб, APK пересобирать не нужно.
1. Реализуй и **протестируй**:
   - `npm run build:www`, раздать `www/` локально: `python3 -m http.server <порт> --bind 127.0.0.1` в папке `www` (порты 8765 и `localhost` могут занимать чужие сессии, бери другой порт и `127.0.0.1`).
   - Открыть во встроенном браузере. Объект `S` и функции не глобальны для инструмента javascript: подставляй данные через `localStorage['fin-mvp-v1']` и перезагрузку (подойдёт настоящая копия владельца из `lucky_finance_backup`), проверяй через DOM (`document.body.innerText`, `querySelector`, `.click()`).
   - Консоль без ошибок (`navigator.vibrate` в браузере нормален).
2. Подними `VERSION` в `index.html`, добавь запись сверху в `CHANGELOG` (храним 5 последних, лишнюю снизу удали). Добавь запись в `docs/DECISIONS.md`.
3. `npm run sync` (пересоберёт `www/` и `version.json` с хешами).
4. `git add -A && git commit -m "Release X.Y: …"` и `git push origin main`.
5. Подожди, пока `https://godoffear.github.io/lucky_finance/version.json?x=<случайное>` покажет новую версию. Сверь SHA-256 всех файлов с `version.json` (node fetch; при таймауте IPv6: `node --dns-result-order=ipv4first`).
6. Если сборка Pages застряла или упала: `gh run list -R godoffear/lucky_finance`, затем `gh run rerun <id>` или `gh api -X POST repos/godoffear/lucky_finance/pages/builds`. Две сборки одной версии параллельно не запускай.
7. Сообщи владельцу (см. раздел 1, п. 7): «Ещё → Обновление приложения → Проверить обновление → Обновить сейчас».

**Если менялся нативный код** (`android/`, плагины, разрешения): подними `versionCode` и `versionName` в `android/app/build.gradle` и `minApk` в `package.json`, `npm run sync`, `./gradlew assembleDebug` в `android/` (JDK 21, подпись общим debug-ключом), `npm run release:apk` (кладёт APK в `apk/LuckyFinance.apk`, пишет хеш в `version.json`), затем выкладывай как выше. Пока на телефоне APK старее `minApk`, веб-обновления не применяются: владельцу нужно будет установить APK (в приложении: «Ещё → Обновление приложения», или прямая ссылка на Pages). Скажи ему об этом заранее.

Страховка в приложении: если обновлённая веб-версия не запустилась 3 раза подряд, оно откатывается на встроенную. Всё равно проверяй до публикации.

## 7. Подводные камни
- Миграции в `normalize()` разовые, по флагам в `settings`, и идут **до** `sanitize(s)`, иначе тот выбросит неизвестные подкатегории.
- На macOS `sed -i` требует суффикс (`sed -i ''`), для сложных правок надёжнее python.
- Не публикуй две сборки Pages одной версии параллельно.
- Samsung и службы: доступ к уведомлениям включается вручную, у установленного APK бывает «ограниченные настройки».
- Нативный эмулятор Medium_Phone_API_37.0 нестабилен на 8 ГБ RAM: запускать с `-memory 2560 -cores 2 -gpu host -no-snapshot`, тест через `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`.
